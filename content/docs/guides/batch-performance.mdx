# Batch Evaluation & Performance Best Practices

Evaluating hundreds or thousands of synthetic images requires careful selection of the invocation paradigm. Because deep learning evaluation backbones (such as CLIP, LPIPS, Inception-v3, and PickScore) require substantial memory allocation and weight initialization from disk, improper execution patterns introduce severe cold-start friction.

---

## Quantitative Comparison of the 4 Modalities

| Invocation Modality | Execution Mechanism | Model Weight Initializations ($N$ samples) | Process Overhead | Typical Latency (10 images, CLIP) | Recommendation |
| :--- | :--- | :---: | :--- | :---: | :---: |
| **Form 1: Multiple CLI Processes**<br />`for f in *.png; do image-evaluator ...` | Spawns fresh OS subshell & Python interpreter per image | **$N$ times** | Massive: ~0.5s interpreter boot + ~2.0s model weight disk I/O per image | **~25 – 35 seconds** | **Anti-Pattern** (Never use in loops) |
| **Form 2: Native CLI Directory Mode**<br />`image-evaluator --image folder/ ...` | Single OS process; CLI loads weights once and iterates internal files | **1 time** | Low: 1 interpreter startup + 1 weight load; purely amortized disk I/O | **~2 – 3 seconds** | **Recommended** (For Shell & CI/CD) |
| **Form 3: Repeated Python `evaluate(...)`**<br />`for img in imgs: evaluate(...)` | Single Python process; `core.py` builds fresh `Predictor` per call | **$N$ times** | Moderate: zero OS process boot, but repeatedly constructs `torch.nn.Module` | **~10 – 18 seconds** | Use only for ad-hoc one-off calls |
| **Form 4: Direct Predictor Reuse**<br />`pred = ClipScorePredictor(); pred(...)` | Single Python process; Predictor instance stays resident in memory | **1 time** | Optimal: zero redundant allocation; pure pipelined tensor inference | **~1.5 – 2.0 seconds** | **Recommended** (For Python Pipelines) |

## Standard Code Paradigms

### Paradigm 1: Native CLI Directory Mode (Form 2)

When orchestrating evaluations via shell scripts or CI/CD pipelines, always pass directory paths directly to `--image` and `--reference`:

<Tabs items={["T2I Text Alignment", "Pairwise Fidelity Triad"]}>
  <Tab value="T2I Text Alignment">
    ```bash
    # Evaluates all images in directory against the prompt with a single model load
    image-evaluator --metrics clip \
        --image ./generated_samples/ \
        --prompt "a majestic mountain range at sunrise" \
        --format json > results.json
    ```
  </Tab>
  <Tab value="Pairwise Fidelity Triad">
    ```bash
    # Pairs files by stem (e.g. img_01.png with img_01.png) and calculates folder-level averages
    image-evaluator --metrics lpips ssim psnr \
        --image ./generated_samples/ \
        --reference ./ground_truth/ \
        --format json > results.json
    ```
  </Tab>
</Tabs>

### Paradigm 2: Python Native Predictor Reuse (Form 4)

For Python services, training scripts, and custom evaluation loops, instantiate the exported `Predictor` class outside the loop and reuse its evaluation methods across samples:

```python
from PIL import Image
from image_evaluator import ClipScorePredictor, LPIPSPredictor

# Step 1: Instantiate predictors once (weights stay resident in memory/GPU)
clip_pred = ClipScorePredictor(device="cpu")
lpips_pred = LPIPSPredictor(device="cpu")

samples = [
    ("gen_01.png", "ref_01.png", "a cybernetic wolf in neon city"),
    ("gen_02.png", "ref_02.png", "an astronaut floating in deep space"),
]

# Step 2: Iterate over samples with zero model reloading overhead
results = []
for gen_path, ref_path, prompt in samples:
    clip_score = clip_pred.evaluate_clip_score(gen_path, prompt)
    lpips_score = lpips_pred.evaluate_lpips(ref_path, gen_path)
    
    results.append({
        "sample": gen_path,
        "clip": clip_score,
        "lpips": lpips_score,
    })

print(f"Evaluated {len(results)} samples without reloading weights.")
```

### In-Memory Tensor / PIL Stream Batching

All Predictor classes support direct in-memory evaluation of `PIL.Image` objects, avoiding disk I/O entirely:

```python
from PIL import Image
from image_evaluator import SSIMPredictor, PSNRPredictor

ssim_pred = SSIMPredictor()
psnr_pred = PSNRPredictor()

# In-memory batch evaluation
images = [Image.new("RGB", (128, 128), color=(i * 20, 100, 100)) for i in range(10)]
reference = Image.new("RGB", (128, 128), color=(0, 100, 100))

scores = []
for img in images:
    s = ssim_pred.evaluate_ssim(reference, img)
    p = psnr_pred.evaluate_psnr(reference, img)
    scores.append({"ssim": s, "psnr": p})
```

## Modality Selection Decision Matrix

- **Choose Form 1 (Single CLI)**: Only for ad-hoc terminal checks of single image files or debugging. **Never wrap in shell loops**.
- **Choose Form 2 (CLI Directory)**: When evaluating existing dataset folders from Bash/Zsh scripts without writing Python code.
- **Choose Form 3 (`evaluate(...)`)**: When running exploratory one-off comparisons in interactive Jupyter notebooks where code brevity matters more than throughput.
- **Choose Form 4 (Predictor Reuse)**: For production evaluation services, benchmark sweeps, dataset scoring pipelines, and deep learning training validation loops.
